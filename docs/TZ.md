# ТЗ: приложение «Доска»

Oct 31, 2026 · @pepe

## 1. Общие сведения

«Доска» — личное кроссплатформенное приложение для проектирования игр, программ и сайтов на бесконечных визуальных досках, по образцу Milanote. Первая версия работает полностью офлайн, а доски между ПК и телефоном переносятся через Syncthing.

**Цели**

- Собрать в одном месте всё по проекту: идеи, референсы, задачи, схемы, ТЗ, данные о персонажах и локациях.
- Повторить функциональность Milanote и добавить то, чего в нём нет: связанные сущности, таблицы, схемы и фигуры.
- Одинаково полноценно работать на Windows и на телефоне (Android).

**Аудитория.** Один пользователь, автор проекта. Аккаунты, сервер, совместная работа и монетизация в первую версию не входят.

**Термины**

| Термин | Значение |
| --- | --- |
| Проект | Корневая папка с досками, сущностями и файлами одного проекта (например, одной игры) |
| Доска | Бесконечный холст с элементами; может лежать внутри другой доски |
| Элемент (карточка) | Любой объект на доске: заметка, картинка, задача, таблица, стрелка и т. д. |
| Сущность | Объект проекта с полями (НПС, локация, предмет, экран), который можно показать на нескольких досках сразу |
| Тип сущности | Шаблон полей для сущностей одного вида, например «НПС: имя, роль, локация, портрет» |
| Шаблон доски | Готовая заготовка доски с элементами для типовой задачи |

## 2. Платформы и технический стек

Одна кодовая база на веб-технологиях, упакованная в нативные приложения через Tauri 2.

**Платформы первой очереди:** Windows 10/11 (установщик .msi/.exe), Android (.apk). iOS, macOS и Linux собираются из того же кода позже, без переделки.

| Слой | Технология | Зачем |
| --- | --- | --- |
| Оболочка приложения | Tauri 2 (Rust) | Нативные сборки под Windows, Android, iOS; доступ к файлам |
| Интерфейс | React + TypeScript + Vite | Один код интерфейса для всех платформ |
| Состояние | Zustand | Лёгкое хранилище состояния UI (выделение, инструмент, зум) |
| Данные досок | Yjs (CRDT) | Слияние правок с ПК и телефона без конфликтов; undo/redo |
| Холст | DOM + CSS transform, SVG-слой для стрелок и фигур | Живой текст в карточках, выделение и копирование из коробки |
| Текстовый редактор | TipTap (ProseMirror) + y-prosemirror | Rich text в заметках, синхронизация текста через Yjs |
| Поиск | MiniSearch | Полнотекстовый поиск офлайн, с русской морфологией через стеммер |
| Локализация | i18next | Строки в JSON-файлах, новый язык = новый файл |
| Экспорт | html-to-image, jsPDF | PNG и PDF доски |
| Синхронизация | Syncthing (внешняя программа) | Перенос папки проекта между устройствами без сервера |

Конкретные библиотеки (Zustand, MiniSearch, jsPDF) можно заменить на этапе прототипа; неизменными остаются Tauri 2, React и Yjs.

## 3. Структура и навигация

Иерархия: **Проекты → Доски (с любой глубиной вложенности) → Элементы**. Сущности и файлы принадлежат проекту целиком, а не отдельной доске.

**Экраны**

1. **Главный экран** — список проектов плитками с обложкой, датой изменения и кнопкой «Новый проект» (пустой или из шаблона).
2. **Доска** — холст, панель инструментов слева (на телефоне снизу), хлебные крошки сверху: «Проект / Доска / Поддоска».
3. **Дерево проекта** — боковая панель со всеми досками проекта, можно скрыть.
4. **Библиотека сущностей** — все НПС, локации и другие объекты проекта таблицей или плитками, с фильтрами по типу и тегам (см. раздел 6).
5. **Поиск** — окно по Ctrl+K с поиском по всем доскам и сущностям.
6. **Корзина** — удалённые доски и элементы хранятся 30 дней, их можно восстановить.
7. **Настройки** — тема, язык, папка хранения проектов, горячие клавиши, резервные копии.

**Навигация**

- Двойной клик (тап) по карточке доски открывает вложенную доску; «Назад» и хлебные крошки возвращают на уровень выше.
- Для каждой доски запоминается последний масштаб и позиция.
- Карточку можно перетащить в другую доску: бросить на карточку доски или на хлебную крошку.
- Избранное: звёздочка на доске добавляет её в быстрый доступ на главном экране.

## 4. Холст и работа с элементами

Холст бесконечный, плавный (60 кадров/с) и одинаково удобен мышью, тачпадом и пальцем.

**Навигация по холсту**

- Панорама: пробел + перетаскивание, средняя кнопка мыши, два пальца на тачпаде или экране.
- Масштаб 10–400 %: Ctrl + колесо или pinch, всегда к точке под курсором/пальцами.
- «Показать всё» (Shift+1), «100 %» (Shift+0), мини-карта в углу (включается в настройках).

**Создание элементов**

- Перетаскивание с панели инструментов на холст.
- Двойной клик по пустому месту создаёт заметку.
- Вставка из буфера (Ctrl+V): картинка → карточка-изображение, ссылка → карточка-ссылка, текст → заметка, таблица из Excel → таблица.
- Drag&drop файлов из проводника; на телефоне — из галереи, камеры и меню «Поделиться».

**Работа с элементами**

- Выделение: клик, Shift+клик, рамка, Ctrl+A.
- Перемещение и изменение размера; привязка к сетке и направляющие к соседним карточкам (отключаются зажатым Alt).
- Выравнивание и распределение выделенных элементов.
- Копировать / вырезать / вставить / дублировать (Ctrl+D), в том числе между досками.
- Порядок слоёв (выше/ниже), блокировка элемента от случайного сдвига.
- Цвет карточки из палитры (10–12 цветов, читаемых в обеих темах).
- Контекстное меню по правому клику или долгому нажатию.
- Отмена и повтор (Ctrl+Z / Ctrl+Shift+Z), минимум 100 шагов на доску.
- Автосохранение каждого действия, кнопки «Сохранить» нет.

## 6. Сущности: один объект на многих досках

Сущность хранится в проекте один раз, а на досках лежат только её представления; правка в любом месте сразу видна везде. Для игр это НПС, локации, предметы, квесты; для программ и сайтов — экраны, фичи, API-методы, сущности БД.

**Пример.** На доске «НПС» лежат карточки всех персонажей. На доске локации «Таверна» лежит карточка того же трактирщика. Переименовали его или сменили портрет на любой из досок — изменение сразу на обеих.

**Типы сущностей**

- Пользователь сам создаёт типы и их поля: название, иконка, цвет, список полей.
- Типы полей: текст, длинный текст (rich text), число, да/нет, список вариантов, несколько вариантов, изображение, дата, ссылка, **связь с другой сущностью**.
- Встроенные типы: «НПС» (имя, портрет, роль, описание, локация → связь, предметы → связи), «Локация» (название, изображение, описание, родительская локация → связь), «Предмет» (название, изображение, тип, описание, характеристики). Набор полей — предложение, пользователь дополняет его сам.
- Изменение набора полей типа применяется ко всем его сущностям; удалённое поле скрывается, а не теряет данные до очистки корзины.

**Связи между сущностями**

- Поле «Локация» у НПС ссылается на сущность «Таверна».
- Связи двусторонние: у «Таверны» автоматически появляется список «НПС здесь».
- У каждой сущности есть блок «Упоминания»: все доски, где она лежит, и заметки, где о ней написано.
- В любом тексте можно упомянуть сущность через `@` (или `[[`): появляется кликабельный чип с актуальным названием.

**Как сущность выглядит на доске**

- Вид выбирается для каждого размещения: «чип» (иконка + имя), «карточка» (картинка + 3–5 главных полей), «полный» (все поля).
- Размер, положение и вид у каждой доски свои, а данные общие.
- Удаление карточки с доски убирает только представление. Удалить саму сущность можно только из библиотеки, с предупреждением «используется на N досках».
- Копирование даёт выбор: «вставить ссылку на ту же сущность» или «создать независимую копию».

**Библиотека сущностей** показывает все сущности типа таблицей (строка = сущность, столбец = поле) или плитками, с сортировкой и фильтрами. Из неё сущность перетаскивается на любую доску.

## 7. Теги, поиск, шаблоны

**Теги**

- Теги общие на весь проект, у каждого свой цвет; вложенные теги через `/` (`баг/критичный`).
- Ставятся на любой элемент, доску или сущность; в тексте — через `#тег`.
- Фильтр на доске: «подсветить элементы с тегом», остальные приглушаются.
- Управление тегами: переименование, слияние, удаление сразу везде.

**Поиск**

- Ctrl+K: одно поле для поиска досок, элементов, сущностей и команд («новая доска», «тёмная тема»).
- Ищет по тексту заметок, подписям, именам файлов, ячейкам таблиц, полям сущностей; учитывает русские словоформы и опечатки.
- Фильтры: тип элемента, тег, доска, дата изменения, «невыполненные задачи».
- Клик по результату открывает доску и подсвечивает элемент. Ctrl+F ищет только на текущей доске.

**Шаблоны досок**

- Встроенные: «ТЗ программы», «Архитектура и схема БД», «Карта экранов сайта», «Гейм-дизайн документ», «Персонажи и НПС», «Локации и мир», «Сюжет и квесты», «Мудборд», «Канбан задач», «Роадмап».
- «Сохранить как шаблон» для любой доски, вместе с вложенными досками и типами сущностей.
- **Шаблон проекта**: набор досок и типов сущностей, например «Игра» (НПС, Локации, Предметы, Квесты, GDD, Задачи) или «Сайт» (ТЗ, Экраны, API, БД, Задачи).
- Шаблоны хранятся файлами и синхронизируются вместе с проектами.

## 8. Хранение данных и синхронизация через Syncthing

Каждое устройство пишет только в свои файлы, а чужие только читает и сливает через Yjs. Поэтому Syncthing никогда не видит одновременных правок одного файла и не создаёт конфликтных копий `.sync-conflict`, даже если одну доску правили на ПК и телефоне без связи.

Каждое приложение пишет только в выделенную папку, а папку другого устройства только читает; Syncthing лишь копирует файлы.

**Структура папки проекта**

```
МояИгра.doska/
  project.json            — название, версия формата, id проекта
  data/
    <deviceId>/           — папка ОДНОГО устройства, пишет только оно
      <docId>.snapshot    — сжатое состояние документа Yjs
      <docId>.log         — журнал новых правок (только дописывается)
  assets/
    <sha256>.<ext>        — картинки и файлы; имя = хэш, файл никогда не меняется
  templates/              — шаблоны проекта
  .stignore               — исключения для Syncthing (временные файлы, кэш поиска)
```

`docId` — это либо отдельная доска, либо общий документ проекта (дерево досок, теги, типы и сами сущности). Доски загружаются по отдельности, поэтому большой проект открывается быстро.

**Как работает синхронизация**

1. Правка на устройстве дописывается в его `<docId>.log` (с накоплением до 1–2 с).
2. Syncthing копирует изменённые файлы на другие устройства, когда они видят друг друга.
3. Приложение следит за папкой (file watcher, на телефоне — проверка при открытии и раз в несколько секунд), читает новые правки чужих устройств и сливает их в открытую доску без перезагрузки.
4. Когда журнал вырастает (скажем, > 1 МБ), устройство сжимает его в свой `.snapshot` и очищает свой `.log`. Чужие файлы оно не трогает.
5. Файлы в `assets/` неизменяемы, поэтому конфликтов в них тоже не бывает. Если картинка ещё не доехала, на карточке видна заглушка «файл синхронизируется».

**Требования к приложению**

- В настройках выбирается «папка проектов»; её же пользователь добавляет в Syncthing на каждом устройстве. Встроенная инструкция по настройке.
- У каждого устройства постоянный `deviceId` и понятное имя («Домашний ПК», «Телефон»).
- Индикатор в интерфейсе: когда последний раз пришли правки с каждого устройства.
- Файлы `.sync-conflict` и повреждённые журналы не ломают проект: приложение сливает их так же, как обычные правки, и пишет предупреждение в журнал.
- Локальные резервные копии: раз в сутки архив проекта в отдельную папку вне Syncthing, хранится 14 последних.
- История версий доски: снимок раз в час работы, просмотр и восстановление (этап 8).
- Формат данных версионируется: новая версия приложения читает старые проекты, а старая версия сообщает «обновите приложение» вместо порчи данных.

**Syncthing на устройствах**

| Платформа | Клиент Syncthing | Замечание |
| --- | --- | --- |
| Windows | Официальный Syncthing (или SyncTrayzor) | Без ограничений |
| Android | Syncthing-Fork | Приложению нужен доступ к папке через системный выбор папки |
| iOS | Официального клиента нет; сторонний Möbius Sync | Не в первой версии; при переходе на iOS проверить доступ к папке через «Файлы» |

Архитектура не привязана к Syncthing: та же папка будет работать через Google Drive, OneDrive или флешку, а позже можно добавить собственный сервер синхронизации.

## 9. Экспорт, оформление, локализация, мобильная версия

**Экспорт**

- **PNG**: вся доска или выделенные элементы; масштаб 1× / 2× / 3×; прозрачный или цветной фон.
- **PDF**: доска на одной странице или разбивка на листы A4/A3; вложенные доски по желанию отдельными страницами.
- **Markdown**: доска как документ. Порядок — сверху вниз и слева направо; заголовки → `#`, колонки → разделы, чек-листы → `- [ ]`, таблицы → таблицы markdown, картинки → файлы в папке рядом, сущности → список полей. Можно экспортировать весь проект папкой .md-файлов (удобно для GitHub и Obsidian).
- Импорт (этап 8): Markdown-файлы, папка картинок.

**Оформление**

- Светлая и тёмная тема: вручную или «как в системе».
- Все цвета задаются переменными (дизайн-токенами), поэтому новую тему можно добавить одним файлом.
- Цвета карточек подобраны так, чтобы текст читался в обеих темах (контраст не ниже WCAG AA).
- Фон доски: сплошной, точки, сетка; свой цвет у каждой доски.

**Локализация**

- В первой версии только русский.
- Ни одной строки интерфейса в коде: все тексты в `locales/ru.json` по ключам (`toolbar.addNote`).
- Новый язык = копия `ru.json` с переводом, без правки кода; язык появляется в настройках автоматически.
- Множественные числа по правилам языка («1 элемент, 3 элемента, 5 элементов»), формат дат и чисел через `Intl`.
- Вёрстка выдерживает строки на 30–40 % длиннее русских.

**Мобильная версия (полное редактирование)**

- Все функции десктопа доступны на телефоне.
- Жесты: один палец по пустому месту — панорама; два пальца — зум; долгое нажатие — меню и выделение; перетаскивание карточки после тапа.
- Панель инструментов снизу, свойства элемента в выезжающей панели; зоны нажатия не меньше 44×44 pt.
- Редактирование длинного текста и сущностей — в полноэкранном режиме, чтобы клавиатура не закрывала карточку.
- Быстрое добавление: фото с камеры, «Поделиться → Доска» из других приложений (ссылка, картинка, текст) во входящие проекта.
- Поддержка планшетов и стилуса (Apple Pencil, S Pen) для рисования.

## 11. Этапы разработки и критерии приёмки

Работа разбита на 9 этапов и \~40 шагов; один шаг = одна сессия ИИ и один коммит. MVP (можно пользоваться на Windows и Android) готов после этапа 3. Подробный список с галочками лежит в репозитории: `docs/ROADMAP.md`.

| Этап | Что входит | Критерий приёмки |
| --- | --- | --- |
| 0. Фундамент и риски | Каркас Tauri 2 + React + TS, линтеры и тесты, сборка Windows и Android, прототипы холста и синхронизации | 1000 карточек при 60 кадрах/с на ПК и телефоне; правки с ПК и телефона сливаются через Syncthing без потерь |
| 1. Ядро данных | Модель данных, хранилище (журналы, снимки, сжатие), слежение за папкой, команды, undo/redo, корзина, резервные копии | Тесты слияния двух устройств и обрыва записи зелёные; формат описан в `docs/format.md` |
| 2. Холст | Камера, зум, жесты, виртуализация, выделение, перемещение, ресайз, привязка, буфер обмена, горячие клавиши | Все действия раздела 4 работают мышью и пальцем на тестовых карточках |
| 3. MVP: доски и базовые элементы | Главный экран, дерево досок, заметка, заголовок, изображение, колонка, вложенная доска, стрелка, чек-лист, темы, i18n, настройки, мобильный интерфейс | Спроектировать небольшую игру на ПК, продолжить на телефоне, увидеть правки на ПК |
| 4. Сущности | Типы и поля, НПС / Локация / Предмет, карточка на доске, связи и обратные связи, упоминания `@`, библиотека | Правка НПС на доске «НПС» видна на доске локации и на телефоне |
| 5. Остальные элементы | Таблица, фигуры для схем, ссылка с превью, файл, видео/аудио, цвет | Каждый элемент добавлен одной папкой в `src/elements/` без правок холста |
| 6. Организация | Теги, поиск Ctrl+K, шаблоны досок и проектов «Игра», «Сайт» | Поиск за 200 мс на 10 000 элементов; проект «Игра» создаётся из шаблона |
| 7. Экспорт | PNG, PDF, Markdown (доска и весь проект) | Экспорт тестовой доски со всеми типами элементов совпадает с эталоном |
| 8. Полировка | Рисование, история версий, импорт Markdown, мини-карта, оптимизация, инсталляторы и автообновление | Все нефункциональные требования раздела 10 выполнены |
