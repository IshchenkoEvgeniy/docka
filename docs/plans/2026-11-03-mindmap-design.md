# Проект решения: майнд-карта (интеллект-карта)

Статус: черновик, ждёт одобрения. Дата: 2026-11-03.
Пометка *(моё решение)* — выбор, который сделал Claude, а не пользователь; его можно оспорить.

## Зачем

Раскладывать идеи деревом прямо на доске: ветки квеста, дерево навыков, структуру мира,
карту экранов. Главное отличие «Доски» — сущности, поэтому узлом карты может быть любая
карточка: заметка, НПС, локация, картинка. Карта — это не отдельный виджет, а способ
связать обычные карточки в дерево, которое само выравнивается.

## Цели

- Дерево из любых карточек доски с автоматической раскладкой.
- Добавление веток из меню, клавишами и перетаскиванием карточки на узел.
- Сворачивание веток, наследование цвета, вставка списка как карты и вывод карты списком.
- Работа на ПК и телефоне, слияние правок двух устройств без поломки дерева.

## Не цели (в этой версии)

- Отдельный элемент «майнд-карта» с текстовыми узлами внутри (как в Miro).
- Несколько родителей у узла, связи «граф», а не «дерево» (для этого есть обычные стрелки).
- Темы оформления карты, стили линий на выбор, иконки и приоритеты на узлах.
- Канбан — отдельная задача, обсуждается позже.

## Анти-цели (провал, даже если «работает»)

- Дерево ломается от правок на двух устройствах (цикл, потерянные ветки, узел с двумя родителями).
- Раскладка «прыгает»: одинаковые данные дают разные позиции на ПК и телефоне.
- Холст или поиск начинают проверять тип элемента (`if (type === 'note')`) — нарушение CLAUDE.md.
- Доска с картой на 500 узлов теряет 60 FPS.

## Решения пользователя

| Вопрос | Решение |
|---|---|
| Узлы | Любые карточки доски |
| Направление | Выбирается у каждой карты |
| Раскладка | Автоматически, но узел можно сдвинуть вручную, и он остаётся на месте |
| В первой версии | Сворачивание веток; цвет ветки наследуется; вставка списка → карта (и карта → список в Markdown) |
| Хранение дерева | Ссылка на родителя у каждой карточки |
| Добавление веток | Пункт контекстного меню; клавиши Tab/Enter; бросить карточку на узел |
| Удаление узла посередине | Спрашивать каждый раз: удалить с веткой или поднять детей к родителю |
| Узел утащили далеко | Остаётся в дереве (ручной сдвиг); убрать из карты — отдельным пунктом меню |

## Варианты хранения (рассмотрены)

1. **Родитель у карточки — выбран.** Одно поле на узле, у каждого узла ровно один родитель;
   правки сливаются по карточке. Линии ветвей вычисляются из данных, разойтись с деревом не могут.
2. Ветви как стрелки с пометкой. Отклонён: стрелку можно удалить или перецепить руками,
   при слиянии узел может получить двух родителей.
3. Отдельная запись «карта» в документе доски. Отклонён: все правки дерева идут в одну
   запись (хуже слияние), карточки не знают, что они узлы.

## Модель данных *(форма полей — моё решение)*

Новое необязательное поле общей части элемента `tree` (Y.Map в записи элемента):

| Поле | Тип | Смысл |
|---|---|---|
| `parentId` | id элемента или `null` | `null` — корень карты |
| `order` | число | Порядок среди братьев; новый узел между соседями получает среднее значение |
| `collapsed` | boolean | Ветки узла скрыты |
| `offset` | `{dx, dy}` или `null` | Ручной сдвиг от вычисленной позиции |
| `direction` | `'right' \| 'both' \| 'down'` | Только у корня |
| `side` | `'left' \| 'right'` или нет | Только у детей корня в режиме `both` |

- Элемент без `tree` — обычная карточка. Карта = корень и все узлы, чья цепочка родителей ведёт к нему.
- Узел карты всегда лежит прямо на доске (`parentId` элемента = `null`). Карточка, брошенная
  на узел из колонки, сначала выходит из колонки *(моё решение)*.
- Может ли тип быть узлом — возможность в реестре (`mindMapNode`, по умолчанию да; рамка — нет).
  Холст про конкретные типы не знает.
- Поднимается `FORMAT_VERSION` (3 → 4). Миграция только меняет номер версии (данных переносить
  не нужно), идемпотентна. Старая версия приложения сообщает «обновите приложение», как требует ТЗ.
  Нужен ADR 0011 и раздел в `docs/format.md`.
- Шаблоны досок: в элемент шаблона добавляется `treeParentIndex` (как `parentIndex` у колонок),
  чтобы «сохранить как шаблон» не терял дерево.

### Починка при чтении *(моё решение)*

Правки двух устройств могут дать некорректное дерево. Каждое чтение строит дерево
детерминированно, одинаково на всех устройствах:

- **Родитель удалён или не существует** → узел цепляется к ближайшему живому предку;
  если такого нет — становится корнем своей карты.
- **Цикл** (телефон перецепил A под B, ПК — B под A) → в цикле узел с наименьшим id
  считается корнем. Данные на диске не переписываются, пока пользователь не изменит узел.
- В журнал пишется предупреждение; приложение не падает.

## Раскладка

- Чистая функция: дерево + размеры узлов + направление → позиции. Живёт в слое без React
  и Yjs (`core`), одинакова на всех устройствах. Учитывает разные размеры карточек.
- Родитель по центру своего поддерева; постоянные отступы между уровнями и братьями
  (значения — на усмотрение исполнителя, в мировых единицах).
- `both`: дети корня делятся на левую и правую стороны; новым узлам сторона выбирается так,
  чтобы стороны были примерно равны по высоте, и запоминается в `side` *(моё решение)*.
- Ручной сдвиг применяется к узлу **вместе с его веткой** *(моё решение)*.
- Свёрнутые ветки не занимают места.
- **Когда пересчитывается:** при любом изменении структуры (добавить, удалить, перецепить,
  свернуть, развернуть, сменить направление) — в той же транзакции, что и само действие,
  одним шагом отмены. При изменении размера узла (текст вырос) — тоже, в транзакции
  изменения размера. Сюда же относится карточка сущности, чья записанная высота изменилась
(см. бэклог про высоту сущностей). Пересчитывается только затронутая карта.
- Позиции записываются в обычные `x/y`, поэтому холст, виртуализация, экспорт и старые
  механизмы работают без изменений.

## Поведение

**Создание карты.** Пункт «Майнд-карта» на панели элементов создаёт заметку-корень
«Центральная идея». Пункт меню «Сделать корнем майнд-карты» превращает любую карточку в корень.

**Добавление веток.**
- Контекстное меню узла (и долгое нажатие на телефоне): «Добавить ветку», «Добавить соседнюю».
- Tab — дочерняя заметка, Enter — соседняя, когда узел выделен, но текст не редактируется.
  Новая заметка сразу открывается для ввода. Enter на корне создаёт дочернюю.
  Клавиши регистрируются в общем месте горячих клавиш. Tab и Enter работают только на узле
  карты; на обычной карточке они ничего не меняют, карта начинается пунктом меню
  «Сделать корнем» *(моё решение: не отнимать у Tab навигацию с клавиатуры)*.
- Перетаскивание карточки на узел: при наведении узел подсвечивается, при отпускании
  карточка становится его последней веткой. Работает для карточек с доски, из библиотеки
  сущностей и с панели элементов.

**Перемещение узла.** Отпустили над другим узлом (не над своим потомком) — узел
перецепляется к нему. Отпустили в пустом месте — запоминается ручной сдвиг, узел остаётся
в дереве *(моё решение: перецепление при броске на узел следует из правила «бросить
карточку на узел»)*. Корень тянет за собой всю карту.

**Сворачивание.** У узла с ветками есть кнопка с числом скрытых узлов. Свёрнутые потомки
не рисуются и не выделяются. Переход к результату поиска внутри свёрнутой ветки
разворачивает путь к нему *(моё решение)*. PNG и Markdown выводят карту так, как она
видна: свёрнутые ветки не попадают в картинку, но попадают в Markdown *(моё решение)*.

**Цвет.** Новый узел получает цвет родителя. Линия ветки — цвета дочернего узла. При смене
цвета узла с ветками в меню есть «Применить цвет ко всей ветке» *(моё решение: цвет
копируется при создании, а не вычисляется, — так проще слияние)*.

**Удаление.** Удаление узла с ветками открывает диалог: «Удалить с ветками» или
«Только этот узел — ветки перейдут к родителю». Для корня: «Удалить всю карту» или
«Убрать только карту — карточки останутся на доске» *(вариант для корня — моё решение)*.
Лист удаляется без вопроса. Удалённое с ветками восстанавливается из корзины вместе.

**Убрать из карты.** Пункт меню «Отделить ветку»: узел с ветками становится отдельной
картой. Для листа — «Убрать из карты» (обычная карточка).

**Направление.** В меню корня: «Вправо», «В обе стороны», «Вниз».

**Рамки.** Рамка переносит карту целиком, только если корень внутри рамки; иначе узлы карты
при переносе рамки пропускаются *(моё решение: иначе раскладка и рамка будут спорить)*.

**Закрепление.** Закреплённый корень не даёт тащить карту; закреплённый узел не сдвигается
вручную, но раскладка его двигает *(моё решение)*.

**Копирование и дублирование.** Связи сохраняются внутри скопированного; узел, чей родитель
не скопирован, становится корнем новой карты. Работает и между досками.

## Линии ветвей

Отдельный слой, как у стрелок: изогнутые линии от стороны родителя к стороне ребёнка,
цвета ребёнка. Это не стрелки: они не выделяются и не правятся. Рисуются и в PNG-экспорте.

## Текст: список ↔ карта

- **Вставка.** Текст, где есть вложенный список хотя бы на двух уровнях (маркеры `-`, `*`,
  `+`, нумерация или отступы), вставляется как карта: один пункт верхнего уровня — корень,
  несколько — их общий корень «Новая карта». Одноуровневый список вставляется заметкой,
  как сейчас. В контекстном меню вставки есть «Вставить как майнд-карту» для любого текста
  *(порог «два уровня» — моё решение, чтобы не сломать привычную вставку)*.
- **Вывод.** Карта в Markdown и простом тексте — вложенный список; каждый узел даёт строку
  через `toPlainText`/`toMarkdown` своего типа (первая строка). Нужно для шага 7.3 и для копирования.

## Производительность

Раскладка — O(n) по узлам карты. Цель: перераскладка карты на 500 узлов укладывается в один
кадр; доска с картой на 500 узлов — 60 FPS. Бенчмарк из этапа 0 расширяется картой.

## Тесты

- Схема `tree`, миграция 3 → 4 («старый проект → новый»), идемпотентность.
- Починка: удалённый родитель, цикл от двух устройств, одинаковый результат на обоих.
- Раскладка: три направления, разные размеры, сворачивание, ручной сдвиг, детерминированность.
- Команды: каждая — одна транзакция и один шаг отмены.
- Список ↔ карта в обе стороны.
- e2e: создать карту, Tab/Enter, бросить сущность на узел, свернуть, удалить с диалогом,
  вставить список, PNG-экспорт с линиями, мобильная ширина.

## Шаги в ROADMAP (новый этап 6Б, перед этапом 7)

- 6Б.1 ADR 0011, формат 4: поле `tree`, схема, миграция, починка при чтении, тесты слияния.
- 6Б.2 Раскладка и команды карты (создать, ветка, соседняя, прицепить, перецепить, отделить,
  удалить в двух режимах, свернуть, направление, ручной сдвиг).
- 6Б.3 Отрисовка: слой линий, кнопка сворачивания со счётчиком, скрытие свёрнутого, PNG.
- 6Б.4 Взаимодействие: панель, меню, Tab/Enter, бросок на узел, перетаскивание, диалог
  удаления, рамки, телефон.
- 6Б.5 Список ↔ карта, копирование и дублирование, шаблоны.

Приёмка: на ПК построить карту квеста из заметок и карточек НПС, продолжить на телефоне,
увидеть одинаковое дерево на обоих устройствах.

## Оставлено исполнителю

Точные отступы и размеры, вид кнопки сворачивания, алгоритм раскладки (любой
детерминированный «аккуратного дерева»), где именно лежит модуль раскладки в слоях,
имена команд и ключей i18n.
