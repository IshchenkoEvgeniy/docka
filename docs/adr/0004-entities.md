# 0004. Сущности: данные в документе проекта, на досках — только представления

Дата: 2026-10-31 · Статус: принято

## Контекст

Сущность (НПС, локация, предмет…) хранится в проекте один раз и показывается на многих досках
(ТЗ, раздел 6). Правка на любой доске должна сразу появляться на всех, в том числе на другом
устройстве после синхронизации. Типы сущностей и их поля пользователь меняет сам; связи между
сущностями двусторонние; в тексте сущность упоминается через `@` или `[[`.

Ограничения: каждое устройство пишет только свои файлы и сливает чужие через Yjs (ADR 0002);
доски загружаются по требованию; холст должен оставаться быстрым (ADR 0001).

## Решение

1. **Где лежат данные.** В документе проекта две новые карты: `entityTypes` (типы и их поля) и
   `entities` (сами сущности). Документ проекта открыт всегда, поэтому сущность видна на любой
   доске без загрузки других досок. На доске лежит элемент типа `entity`:
   `data = { entityId, view }`, где `view` — `chip`, `card` или `full`. Размер, место и вид —
   у каждого размещения свои, данные — общие.
2. **Поля — объектом по id** внутри записи типа (вложенные карты Yjs), значения сущности —
   объектом по id поля. Добавление полей и правка разных полей с разных устройств сливаются.
   Множественные значения («несколько вариантов», связь «много») — объект `id → true/false`,
   а не массив: снятые отметки не воскресают и не затирают чужие.
3. **Удалённое поле скрывается** (`deletedAt`), значения остаются до очистки корзины (30 дней),
   затем удаляются и описание поля, и значения у всех сущностей. Сменить вид поля после
   создания нельзя: старые значения стали бы чужого вида. Значение, не подходящее полю,
   при чтении не показывается, но и не стирается.
4. **Длинный текст поля** — `Y.XmlFragment` в карте `texts` записи сущности (как текст заметки,
   ADR 0003). Фрагменты создаются вместе с сущностью для всех полей «длинный текст»; для полей,
   добавленных позже, — при первой правке (риск одновременного первого ввода на двух
   устройствах принят, как для старых заметок).
5. **Обратные связи не хранятся, а вычисляются**: список «НПС здесь» у локации — все сущности,
   чьё поле-связь указывает на неё. Хранить обе стороны значило бы держать их согласованными
   при офлайн-правках двух устройств; вычисление всегда верно. Подпись списка — `backName` поля
   (у встроенных — из перевода).
6. **Упоминание** — встроенный узел `mention` (атрибуты `id`, `label`) в любом тексте
   (TipTap Mention, триггеры `@` и `[[`). Показывается актуальное название сущности; `label` —
   запасной текст, если сущность удалена или текст копируют в другую программу.
7. **Блок «Упоминания» и «используется на N досках»** считаются по запросу: открываются все
   доски проекта (не открытые — закрываются после подсчёта), в каждой ищутся элементы со
   ссылкой на сущность и упоминания в текстах. Индекс не ведётся: его пришлось бы обновлять
   на каждом устройстве при любой правке доски.
8. **Встроенные типы** «НПС», «Локация», «Предмет» создаются миграцией к формату **2** с
   постоянными id (`builtin-npc`, …), в том числе в новых проектах. Названия встроенных типов,
   полей и вариантов хранятся пустыми с ключом `builtin`: интерфейс берёт текст из перевода,
   пока пользователь не переименует. Так в данных нет строк интерфейса, а новый язык
   переводит и встроенные типы.
9. **Отмена.** На доске правки сущностей (документ проекта) и доски — одна история:
   `combineUndoHistories` помнит, в каком документе был последний шаг.
10. **Удаление.** Удаление карточки с доски убирает только представление. Сущность удаляется
    только из библиотеки — в корзину (`deletedAt`), с предупреждением о числе досок.
    При копировании элементов со ссылкой на сущность пользователь выбирает: ссылка на ту же
    сущность или независимая копия.

## Альтернативы

- **Сущность целиком в элементе доски** (копия на каждой доске): правка не видна на других
  досках — противоречит ТЗ.
- **Отдельный документ на каждую сущность:** тысячи файлов на устройство и загрузка по одному
  ради чипа; документ проекта и так открыт. Отказались.
- **Хранить обратные связи** (у локации — список НПС): рассогласование при офлайн-правках.
- **Типы сущностей кодом:** пользователь должен менять поля сам (ТЗ).

## Последствия

- Формат 2: старое приложение не откроет проект и попросит обновиться (вместо заглушек на месте
  сущностей и непонятных данных).
- Если два устройства одновременно впервые мигрируют один проект офлайн и оба успеют поправить
  встроенный тип до синхронизации, правки встроенного типа на одном из них могут потеряться
  (Yjs оставит одну из двух одинаковых записей). Новые поля и сущности с любой стороны
  сохранятся.
- Подсчёт упоминаний открывает все доски проекта — для сотен досок это секунды; показывается
  индикатор. Если станет медленно — кэш индекса на устройстве (вне синхронизации).
- Новая зависимость: `@tiptap/extension-mention` и `@tiptap/suggestion` (официальные пакеты
  TipTap той же версии).
