# 0003. Текст элементов: Y.XmlFragment в записи элемента, редактор только у одного элемента

Дата: 2026-10-31 · Статус: принято

## Контекст

Заметке и заголовку нужен форматированный текст (ТЗ, раздел 5), который правят на нескольких
устройствах офлайн и сливают без потерь. На доске может быть тысяча заметок, а холст должен
оставаться быстрым (ADR 0001).

## Решение

1. **Где лежит текст.** `Y.XmlFragment` в поле `text` записи элемента — рядом с `x`, `y`, `data`
   (раскладка y-prosemirror). Схема элемента это поле не проверяет (zod отбрасывает лишние ключи).
   Плюсы: удаление в корзину, восстановление, отмена и очистка корзины захватывают текст
   без отдельного кода; правки с разных устройств сливаются посимвольно.
2. **Создаётся вместе с элементом** в одной транзакции (`createElements` с `richText`): если бы
   фрагмент создавался «при первой правке», два устройства могли бы создать его одновременно,
   и один текст затёр бы другой. Исключение — старые заметки этапа 2 (`data.text`): им текст
   создаётся при входе в правку (`TEXT_INIT_ORIGIN`), риск принят — таких заметок мало.
3. **Редактор только у правящегося элемента.** Остальные показывают текст без редактора:
   `fragmentToRich` → дерево узлов → React (`RichTextView`), только известные узлы и пометки.
   Редактор — TipTap (StarterKit без своей истории и без блоков кода) + `ySyncPlugin`.
4. **Одна история отмены.** Правки редактора идут в историю доски (`mergeOrigins`): набор
   текста склеивается в шаги по паузам 0,7 с, но никогда не склеивается с командами.
   `yUndoPlugin` не используется: при закрытии редактора он уничтожает переданный ему
   UndoManager. Ctrl+Z в редакторе вызывает отмену доски.
5. **Высота растёт по тексту.** У заметки и заголовка тянется только ширина; высота
   измеряется и пишется в запись (`MEASURE_ORIGIN`, не шаг отмены), но **только** пока элемент
   правят или сразу после создания и изменения ширины на этом устройстве. Иначе устройства с
   разными шрифтами бесконечно переписывали бы высоту друг за другом.
6. **Нейтральный вид текста** (`RichNode` в core) — для буфера обмена, поиска, экспорта:
   слои ниже элементов не зависят от схемы редактора.

## Альтернативы

- **Текст строкой в `data.text`** (как на этапе 2): правка с двух устройств — последняя
  побеждает, вторая теряется целиком. Отказались.
- **Отдельная карта `texts` в документе доски:** корзину, восстановление и копирование
  пришлось бы делать для текста отдельно. Отказались.
- **Редактор у каждой карточки:** тысяча экземпляров ProseMirror — сотни мегабайт и секунды
  на открытие доски. Отказались.

## Последствия

- Чужая правка текста меняет объект элемента в снимке доски — перерисовывается только он.
- Ссылки на доске не кликабельны (переход увёл бы окно приложения); открытие ссылок — позже,
  через системный браузер.
- Размер сборки вырос (~+300 КБ за TipTap/ProseMirror) — для локального приложения допустимо.
