# 0002. Доступ к папке проекта: собственные Rust-команды на обычных путях

Дата: 2026-10-31 · Статус: принято (Android-доступ к общей памяти — см. «Последствия»)

## Контекст

Проект — обычная папка, которую синхронизирует Syncthing (ТЗ, раздел 8). Нужны чтение, атомарная
запись, дописывание, список файлов и слежение за изменениями на Windows и Android.
Журналы и снимки Yjs — двоичные данные, их размер — от байтов до мегабайт.

## Решение

1. **Свои команды Rust** (`src-tauri/src/storage`) на `std::fs` по обычным путям, а не
   официальный плагин `plugin-fs` и не Storage Access Framework Android. Syncthing на Android
   синхронизирует обычную папку (`/storage/emulated/0/...`), и работать с ней по пути проще и
   предсказуемее.
2. **Безопасность:** команды работают только внутри папок, которые пользователь открыл
   (`storage_open_root` регистрирует канонический путь). Относительные пути проверяются:
   запрещены пустые сегменты, `.`, `..`, абсолютные пути, `\`, `:`, управляющие символы.
   Команды доступны только локальному содержимому приложения (Tauri не пускает внешние адреса).
3. **Атомарная запись:** `<файл>.doska-tmp` рядом → запись → `fsync` → переименование поверх.
   Временные файлы не попадают в списки и события.
4. **Двоичные данные без JSON:** запись — сырым телом запроса (корень и путь — в заголовках
   `x-doska-root`/`x-doska-path`, закодированы `encodeURIComponent`, чтобы кириллица проходила);
   чтение — сырым ответом, первый байт: 0 — файла нет, 1 — дальше содержимое.
5. **Слежение** — библиотека `notify` (ReadDirectoryChangesW на Windows, inotify на Linux/Android),
   событие `storage://changed` с относительными путями. **Событие — подсказка, а не точный
   список:** если новая папка создаётся вместе с файлом, ОС может сообщить только о папке
   (наблюдение за ней подключается позже). Поэтому слой данных по любому событию в `data/`
   перечитывает папки устройств целиком (шаг 1.5).
6. Команды асинхронные — ввод-вывод не блокирует главный поток интерфейса.

## Альтернативы

- **`@tauri-apps/plugin-fs`:** нет атомарной записи одной операцией, двоичные данные и область
  доступа на Android сложнее; слежение — отдельная функция плагина. Отклонено.
- **Storage Access Framework (выбор папки через системный диалог Android):** даёт `content://`
  URI вместо путей, нет надёжного слежения и дописывания. Отклонено для первой версии.

## Последствия

- Проверено тестами: пути (`paths.rs`), файловые операции (`files.rs`), реестр папок
  (`roots.rs`) и сквозные тесты через IPC Tauri (`ipc_tests.rs`): запись/чтение/список,
  кириллица в путях, отказ вне открытой папки и при `../`, события слежения.
- **Android:** чтобы читать и писать общую папку Syncthing, приложению нужно разрешение
  «Доступ ко всем файлам» (`MANAGE_EXTERNAL_STORAGE`) и экран, отправляющий пользователя в
  настройки за ним. Это делается перед шагом 0.6 (проверка Syncthing вживую). Приложение не
  публикуется в Google Play, поэтому ограничения магазина на это разрешение не мешают.
- Шаблон `*.doska-tmp` нужно добавить в `.stignore`, который приложение создаёт в папке проекта
  (шаг 1.4), чтобы Syncthing не пытался синхронизировать временные файлы.
