## Этап 0. Фундамент и проверка рисков

- [x] 0.1 Каркас: Tauri 2 + React + TypeScript (strict) + Vite + pnpm. ESLint, Prettier, Vitest, dependency-cruiser с правилами слоёв из CLAUDE.md. Скрипт `pnpm check` = typecheck + lint + test + deps. Пустые папки слоёв с `index.ts`.
- [ ] 0.2 Сборка и запуск на Windows (`pnpm tauri build`), инструкция в `docs/BUILD.md`.
  _Статус: `pnpm tauri dev` и отладочная сборка `doska.exe` работают на ПК; осталось собрать установщики `pnpm tauri build`._
- [x] 0.3 Сборка и запуск на Android (эмулятор + реальный телефон), дополнить `docs/BUILD.md`.
- [x] 0.4 Прототип холста: 1000 случайных карточек, пан и зум мышью и пальцами, счётчик FPS. Замер на ПК и телефоне, результат в `docs/adr/0001-canvas-dom.md`.
  _Итог: ПК — пан 143, зум 132, обзор 76 FPS; телефон — 49 / 54 / 60 FPS. Рывки при монтаже карточек → шаг 2.2._
- [x] 0.5 Прототип хранения: Yjs-документ, журнал и снимок на устройство, слияние двух папок `data/<deviceId>/`. Тест: две «виртуальные» копии правят офлайн → слияние без потерь.
- [ ] 0.6 Проверка Syncthing вживую: ПК ↔ Android, правки на обоих без связи, затем синхронизация. Результат в `docs/adr/0002-sync-syncthing.md`.
  _Перенесено: выполняется сразу после шага 1.5. Перед ним — доступ Android-приложения к общей папке (MANAGE_EXTERNAL_STORAGE, ADR 0002)._

Приёмка: 60 FPS на 1000 карточках на обоих устройствах; слияние через Syncthing без потерь и без `.sync-conflict`.

## Бэклог

Сюда записываются проблемы и идеи, найденные вне текущего шага.

- Стрелки к карточкам внутри колонки крепятся к самой колонке; копирование и вставка стрелок не сделаны.
- Удаление карточки доски не удаляет саму доску (она остаётся в дереве); решить вместе с корзиной.
- Неиспользуемые файлы в assets/ не удаляются: нужна уборка после очистки корзины (с учётом других устройств).
- Ссылки в тексте не открываются: нужен системный браузер через плагин Tauri (opener).
- Заметки, созданные до шага 3.5, хранят высоту 120 и выглядят ниже своей рамки, пока их не отредактируют.
- Название проекта на главном экране берётся из project.json; когда появится переименование проекта, показывать название из документа проекта (кэшировать в настройках).
- Автопрокрутка холста, когда при перетаскивании или рамке указатель у края экрана.
- В обзорном режиме (масштаб < 50 %) элементы рисуются картинкой и не нажимаются: выделять их можно только рамкой. Решить, нужен ли выбор кликом по картинке.

- `tagIds` элемента хранится массивом: если на двух устройствах офлайн добавить разные теги одному элементу, сохранится один набор. Перевести на Y.Map-множество, когда появятся теги (шаг 6.1).
- Библиотека сущностей: фильтр по тегам — вместе с тегами на шаге 6.1 (сейчас фильтр по типу и названию).
- Вставка карточки сущности в другой проект: сущности там нет — карточка покажет «удалена». Переносить данные сущности в буфере обмена.
- Ctrl+Z в редакторе длинного текста панели сущности отменяет правки сущностей, а не общую историю доски (общая история это учитывает, но шаги доски из редактора не отменить).
- В простой текст и Markdown карточка сущности пока не выводит названия (`toPlainText` не видит документ проекта) — решить на этапе 7.
- Новая карточка сущности рисуется цветом «без цвета», а не цветом типа.
- Высота карточки сущности записывается только после своей правки (ADR 0003): если сущность изменили в панели, рамка выделения может не совпадать с карточкой до следующего изменения размера.
- `useBoardDirectory` на экране проекта создаёт подписку в `useMemo` и снимает её в эффекте: в режиме разработки (StrictMode) названия досок на карточках перестают обновляться. Переделать, как `useProjectEntities`.
- Видео встаёт рамкой 16:10, а не по пропорциям ролика: подстраивать размер по метаданным после загрузки.
- PDF на Android открывается только в программе (в WebView Android нет встроенного просмотра PDF).
- Таблица: ширина столбцов, перестановка строк и столбцов перетаскиванием, вставка из Excel в уже существующую таблицу.
- Фигуры: на ромбе и параллелограмме стрелки крепятся к серединам сторон рамки; точки привязки по углам ромба и ручное перемещение точки крепления.
- Превью ссылок: сайты, отдающие страницу только после JavaScript (часть соцсетей), дают пустое превью.
