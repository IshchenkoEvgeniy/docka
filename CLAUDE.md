# Доска — правила разработки для ИИ

Офлайн-приложение для проектирования игр и программ на бесконечных досках (аналог Milanote).
Платформы: Windows и Android (Tauri 2). Один пользователь, синхронизация через Syncthing.

Документы: ТЗ — `docs/TZ.md`, план — `docs/ROADMAP.md`, формат данных — `docs/format.md`,
архитектурные решения — `docs/adr/`. При противоречии правило из этого файла важнее привычек.

## Порядок работы в каждой сессии

1. Открой `docs/ROADMAP.md`, возьми первый невыполненный шаг. Один шаг = одна сессия = один коммит.
2. Перед кодом напиши короткий план: какие модули меняются, какие интерфейсы появляются.
   Если меняется архитектура, стек или формат данных — сначала ADR в `docs/adr/`, потом код.
3. Пиши код вместе с тестами.
4. Запусти `pnpm check` (typecheck + lint + test + deps). Шаг не готов, пока проверки красные.
5. Отметь шаг в ROADMAP, добавь строку в `docs/CHANGELOG.md`.
6. Делай только текущий шаг. Найденное вне шага — запиши в раздел «Бэклог» ROADMAP.
7. Требование неясно или противоречит ТЗ — спроси, не придумывай.

## Стек (менять только через ADR)

Tauri 2 (Rust) · React + TypeScript strict · Vite · pnpm · Yjs · TipTap + y-prosemirror ·
Zustand · i18next · zod · Vitest · Playwright · ESLint + Prettier · dependency-cruiser.
Новая зависимость — только с обоснованием в сообщении коммита; предпочитай маленькие и живые пакеты.

## Слои

```
src/
  core/      домен: типы, zod-схемы, команды, порты (интерфейсы). Без React, Yjs, Tauri, DOM.
  data/      Yjs-документы, репозитории, журналы и снимки, слияние, undo. Реализует порты хранения.
  platform/  адаптеры Tauri: файлы, watcher, диалоги, буфер обмена. Реализует порты core.
  canvas/    движок холста: камера, координаты, hit-test, выделение, жесты, виртуализация.
             Не знает конкретных типов элементов.
  elements/  папка на тип элемента: note/, image/, column/ ...
  features/  сценарии: projects/, entities/, search/, tags/, templates/, export/, settings/.
  ui/        дизайн-система: токены, кнопки, меню, панели. Без бизнес-логики.
  app/       запуск, провайдеры, роутинг, сборка зависимостей (единственное место, где
             реальные адаптеры platform подставляются в порты).
  i18n/      locales/ru.json
src-tauri/   Rust: только системные операции. Никакой бизнес-логики.
```

Направление зависимостей (проверяет dependency-cruiser, нарушение = красный `pnpm check`):

```
app → features → elements → canvas → data → core
ui  → core (только типы)        platform → core (только порты)
```

- Импорт только «вниз». `core` не импортирует ничего из проекта.
- `platform` импортирует только `app`; остальные работают через порты из `core/ports`.
- Циклические зависимости запрещены.
- В чужую папку `features/*` или `elements/*` — только через её `index.ts` (публичный API).

## Данные

- Источник правды — Yjs-документы в `data/`. Состояние React производно от них.
- Любое изменение данных — через команду из `core/commands` (`createElement`, `moveElements` ...).
  Команда выполняется в одной Yjs-транзакции. Компоненты никогда не пишут в Yjs напрямую.
- Одно действие пользователя = одна транзакция = один шаг undo.
- Хранение по ТЗ, раздел 8: устройство пишет только в `data/<deviceId>/` и в новые файлы `assets/`.
  Запись в чужие файлы запрещена.
- Запись на диск только атомарная (временный файл + переименование) через `platform`.
- Всё, что читается с диска, проходит zod-схему. Битые данные не роняют приложение:
  пропустить, записать в журнал, показать предупреждение.
- Изменение формата: поднять `FORMAT_VERSION`, добавить идемпотентную миграцию в `src/data/migrations.ts`
  и тест «старый проект → новый», обновить `docs/format.md` (раздел «Версии и миграции»).
- Координаты элементов — в мировых единицах холста, не в пикселях экрана. ID — nanoid.

## Элементы — только через реестр

- Новый тип = новая папка в `elements/` + одна строка регистрации в `elements/registry.ts`.
- Папка элемента: `schema.ts`, `definition.ts`, `View.tsx`, при необходимости `Toolbar.tsx`,
  `toMarkdown.ts`, тесты.
- `ElementDefinition`: `type`, `schema`, `defaults`, `View`, `Toolbar?`, `toMarkdown`, `searchText`, `minSize`.
- `switch (element.type)` и `if (type === 'note')` вне реестра запрещены.
  Холст, поиск и экспорт работают только с общим интерфейсом.

## Холст и производительность

- Камера — один `transform` на контейнере; элементы позиционируются в мировых координатах.
- Ре-рендер только изменившихся элементов: подписка по id, `React.memo`, без подписки всего холста
  на весь документ.
- Элементы вне видимой области (плюс запас) не рендерятся.
- Во время перетаскивания позиция меняется локально через `requestAnimationFrame`,
  в Yjs фиксируется на отпускании.
- Ввод — только Pointer Events (мышь, палец, стилус одинаково).
- Бюджет: 60 FPS на 1000 элементах. После изменений холста запускай бенчмарк из этапа 0.

## Код

- TypeScript strict. Запрещены `any`, `!` (non-null), `as` без комментария «почему безопасно»,
  `@ts-ignore`, отключение правил линтера ради прохождения проверки.
- Компонент ≤ 200 строк, функция ≤ 50 строк, файл ≤ 300 строк — иначе раздели.
- Логика не живёт в компонентах: компонент вызывает хук, хук вызывает команду.
- Zustand — только эфемерное UI-состояние (инструмент, выделение, камера, открытые панели).
  Данные документа в Zustand не копируются.
- Имена полные и понятные; компоненты `PascalCase.tsx`, остальное `camelCase.ts`.
- Ошибки не глотаются: понятное сообщение в журнал, пользователю — тост через i18n.
- Нет закомментированного кода, мёртвого кода и TODO без записи в бэклоге.
- Комментарии объясняют «почему», а не «что».
- Не дублируй: третий одинаковый кусок кода — повод вынести общую функцию.
  Но не создавай абстракцию «на будущее» без второго реального использования.

## Интерфейс

- Ни одной строки текста в JSX и коде UI — только `t('область.ключ')`, ключи в `i18n/locales/ru.json`.
  Множественные числа и даты — через i18next и `Intl`.
- Цвета, отступы, радиусы, шрифты, тени — только CSS-переменные из `ui/tokens.css`.
  Каждое значение проверено в светлой и тёмной теме.
- Каждое действие доступно кнопкой или меню, пальцем, и, где уместно, горячей клавишей
  (регистрация в одном месте).
- Мобильные зоны нажатия ≥ 44 px. Кнопки-иконки имеют `aria-label`.

## Платформа (Rust / Tauri)

- В Rust только то, что нельзя сделать в JS: атомарная запись, слежение за папкой, системные пути.
- Команды Tauri узкие и типизированные; входные данные проверяются.
- Разрешения (capabilities) минимальные: доступ только к папке проектов и папке резервных копий.

## Тесты

- `core` и `data` покрыты юнит-тестами: команды, схемы, миграции, слияние двух устройств,
  обрыв записи, повреждённый журнал.
- Каждый элемент: тест схемы и `toMarkdown`.
- Каждый исправленный баг — сначала тест, который его воспроизводит.
- e2e (Playwright) — критерии приёмки этапов из ROADMAP.
- Тесты детерминированы: фейковые часы, детерминированный генератор id, без сети.

## Git

- Conventional Commits на русском: `feat(canvas): выделение рамкой`, `fix(data): ...`.
- В коммите — только текущий шаг. Не коммить с красным `pnpm check`.

## Запрещено

- Запись в Yjs из компонентов; обход команд.
- Импорт «вверх» по слоям и обход публичных `index.ts`.
- `switch` по типу элемента вне реестра.
- Строки интерфейса и цвета в коде.
- Сетевые запросы, кроме превью ссылок; телеметрия.
- Смена стека, формата данных или структуры папок без ADR.
- «Временные» костыли и заглушки, выдаваемые за готовую функцию.

## Если сомневаешься

Выбери самое простое решение, не нарушающее правил выше. Большое изменение раздели на шаги.
Не уверен в требовании — спроси пользователя.
